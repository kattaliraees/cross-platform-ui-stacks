    Language advantages

    The language you write the app in shapes hiring, speed of iteration, and how well an agent can help.

    Dart

    Flutter

    Advantages

    • Quick to learn for Java, C#, Swift and TypeScript developers
    • Sound null safety
    • Compiled ahead of time for release, JIT for stateful hot reload in debug
    • One language for UI and logic, with isolates for parallel work

    Trade-offs

    • Used almost only inside Flutter, so the hiring pool is smaller
    • Less training data for models than JavaScript or Kotlin
    • Has a garbage collector and a runtime you can’t remove
    • Thinner server-side library ecosystem

    TypeScript / JavaScript

    React Native + Expo, Tauri frontends

    Advantages

    • Largest developer pool and package ecosystem
    • Same language on web, mobile and server, so code and people move between them
    • Fastest iteration loop with Fast Refresh
    • Models write it best of any stack here

    Trade-offs

    • Runs as Hermes bytecode, not machine code
    • Types vanish at runtime, so some bugs only show on device
    • Dependency sprawl and version churn
    • One main JavaScript thread to keep unblocked

    Kotlin

    Kotlin Multiplatform + Compose Multiplatform

    Advantages

    • Modern, null-safe, with coroutines for async work
    • Shares logic across Android, iOS, desktop and server
    • Excellent IDE support, and the Compose API matches Android’s
    • Interop with Swift and native views when you need it

    Trade-offs

    • Gradle setup and build times
    • JVM on desktop, Kotlin/Native on iOS, each with its own quirks
    • iOS developers rarely know it
    • expect/actual and source-set setup is where agents slip most

    Rust

    Tauri core, Dioxus, Slint, Makepad, egui, iced, GPUI

    Advantages

    • No garbage collector, memory safety without a runtime
    • Top compute performance and small binaries
    • One language front to back with Dioxus or Tauri’s core
    • Precise compiler errors give an agent something concrete to fix

    Trade-offs

    • Steepest learning curve for a mixed team
    • Slow compiles lengthen the agent edit–run loop
    • Borrow checker fights shared UI state
    • Small UI ecosystem and hiring pool, and APIs that change between releases

    UI markup languages

    Slint’s .slint, Makepad’s DSL

    Advantages

    • Declarative layout that designers can read
    • Live preview or live design while you edit
    • Keeps view code separate from Rust logic

    Trade-offs

    • One more language and toolchain to learn
    • Little training data, so models make more mistakes
    • Small communities and fewer worked examples

    Read this before trusting the numbers

    • Nobody reaches 99.9% shared code. Permissions, push notifications, store configuration, deep links and platform plugins always need some platform-specific code. The “Code share achievable” row and the facts table give realistic ranges, which are my estimates.
    • Scores are relative judgments, not measurements. Performance rows describe typical behavior. For a real decision, build the same representative screen in your top two and measure memory, startup, frame times and battery on your target devices.
    • Differences from my earlier ordered list. At default weights, Slint edges Dioxus and egui edges Makepad. Scoring ecosystem, hiring and agent familiarity explicitly lifts egui, and Dioxus’s default webview and Tier 2 mobile hold it back. Those pairs are close, so treat them as near ties.
    • Fast-moving areas to recheck. Dioxus’s webview-free renderer, Slint and Makepad on iOS and Android, Kotlin/Wasm web support, and Tauri’s mobile plugins.
    • Agentic readiness blends how much correct, current code models have seen, how useful compiler feedback is, and the availability of agent tooling and LLM-readable docs. Flutter and Expo both publish agent-oriented tooling and docs, which is why they lead that group.
